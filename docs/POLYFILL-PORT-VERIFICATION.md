Identical copies are retained in the upstream test snapshot and the Rust crate's `polyfill_fixture.cc`. Original test names, lines, source-body hashes, polygon sizes, flags and loop-expanded counts are in `compatibility/polyfill-ports.json`. `tools/port_polyfill_compact.py` reproduces the cases, native runners, snapshots and manifest. Unknown source revisions or coordinate syntax fail rather than silently generating substitute cases.

The original twelve shared EXPECT sites check vertex usage, repeated indices, internal/boundary edge counts, winding, area and the selected no-zero-area condition. The port preserves all original loop iterations and both plain and beautified results. Degenerate flags continue to suppress the original winding/area checks, not the topology checks. The source defaults `USE_COMBINATIONS_ALL` and `USE_BEAUTIFY` are enabled; optional OBJ preview is disabled and is not represented as implemented file output.

The pinned combination helper has an observable gap: it reverses and cycles `poly_copy` but passes the unchanged `poly` to its sign-flip helper. The Rust port deliberately retains that behaviour, including the repeated executions, rather than claiming that these original assertions exercise true permutations. Four coordinate-sign combinations still execute for each original loop position. A separate corpus below genuinely supplies the transformed coordinates.

The topology test uses a Rust ordered map instead of Blender's unspecified hash-map iteration order. That loop's original observable assertion is solely that each multiplicity is one or two. All original assertions still execute; this representation change does not claim hash-map layout/iteration parity.

## Underlying Rust functionality

`polyfill.rs` implements the pinned ear-clipping algorithm with indexed circular storage, concave/tangent-vertex KD-tree pruning, cached blocking vertices and original ear-selection order. The beautifier builds half edges, evaluates the original area/perimeter rotation cost, maintains the prior ported heap's tie behaviour, rotates diagonals and reconstructs ordered triangles. Original source and LIBGDX attribution are retained.

The implementation provides `triangulate_into`, `triangulate`, `beautify` and `rotation_cost`. It requires finite coordinates and a single boundary with at least three vertices. Safe indexed storage replaces native pointers and arenas. Self-intersecting or degenerate inputs retain the reference index-topology fallback but do not gain a guarantee of non-overlapping geometric coverage. Hole support, complete BMesh integration, allocator/ABI equivalence and performance parity are outside this batch.

## Genuine permutation oracle

`tools/verify_polyfill_oracle.py` compiles unedited original `polyfill_2d.cc`, `polyfill_2d_beautify.cc`, `BLI_heap.cc` and `BLI_memarena.cc`, with the original `cross_poly_v2` and pinned math headers. An explicit malloc/calloc/realloc bridge supplies guarded-allocation entry points; it does not replace triangulation logic and does not establish allocator parity. Source hashes and compiler flags are recorded.

For each of the 29 original polygons, the corpus genuinely supplies every cyclic vertex shift, both orientations and all four x/y sign combinations. This produces **3,064 transformed configurations and 6,128 plain/beautified triangulation results**. Original input float bits and metadata are included in the output alongside **133,968 triangle triplets**.

All **566,512 output words, including exact triangle index order, match** between original C++, native Rust and Node.js WebAssembly. Each complete output is 2,266,048 bytes with SHA-256 `ef003e530f8ce7cdb380b296e03c6e6d838155f5955273d6fd71bcae92358349`. Inputs have SHA-256 `c36e39389a090fcc3f8169570942a7760a671d21b0fed5fd6b48537407cb3897`. The oracle reports 2,528 changed output sequences after beautification; that includes possible triangle reordering and is not a count of distinct quality-improving diagonal flips.

[Immutable oracle report, original drivers, serialised inputs and all outputs](https://github.com/596050/blended/tree/c3edd21e2e953d5275768223b869cbbb9a22d42e/verification/evidence/polyfill-oracle).

This supplemental corpus uses native Rust and **Node.js WebAssembly**, not Chromium. Separately, all 541 original cases execute in diagnostic Chromium and the production workbench is tested at its public Chromium URL. These are different verified layers. The workbench build requires the oracle to succeed before publication, using isolated temporary diagnostic builds that cannot replace the production module. No workflow file was changed for this batch.

The corpus closes the identified original test gap for the stated fixtures; it is not exhaustive over arbitrary polygons and does not add 3,064 upstream test cases.

## Test-first evidence and infrastructure regressions

At source `55ad0076acfe841c390f01e136b408fb79c7e945`, [run 40139574705](https://github.com/596050/blended/actions/runs/40139574705) compiled all 29 original-identity runners before `blended_core::polyfill_cases` existed. It failed with 29 E0433 missing-module resolution diagnostics. This is compilation failure before implementation, not 29 executed failing assertions. The original log hash and artifact archive hash are preserved in [polyfill-test-first-summary.json](../evidence/polyfill-test-first-summary.json). The full original Actions artifact is subject to its retention period; the summary is not presented as the full archived log.

Thirteen new Python regressions check source copies, identities/body hashes, helper preservation, both plain/beautified checks, loop counts, digit-prefixed names, NE operands and required-contract failure handling. No polygon-specific implementation-mutation probe was added in this batch. Earlier families' existing mutation checks still execute in the combined CI run.

The base assertion lock remains unchanged. `tools/contract_registry.py` explicitly requires the new polygon shard and rejects missing shards, wrong reference commits and duplicate identities. Every execution/audit consumer uses the same union of 39 contracts. Removing a runtime group cannot silently reduce the reviewed universe.

## Discovery correction and remaining work

GoogleTest can token-paste digit-prefixed test arguments. The old scanner omitted `3Colinear`, `4Colinear` and six libmv ArrayND dimensional constructor/accessor cases. The updated lexical handling retains preprocessing-number tokens while continuing to mask comments and strings. Eight real source declarations are recovered; they are not automatically counted as newly ported.

The current audit is **5,867 source candidates, 547 reviewed mappings and 5,320 unmapped declarations**. Mappings comprise 541 runtime and six compile-time cases. The complete runtime denominator is still unknown. Five optional half-performance benchmarks, other compile-time/configuration work and extensive application-level families remain unfinished. Keep completion issue #3 open. These mesh-library additions do not constitute a complete Blender editor or rendering engine.
